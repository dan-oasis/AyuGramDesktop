# Организация проекта mTelegram

Состояние: 6 ноября 2026 года. Эта ветка содержит уже перенесённый десктопный код, брендинг mTelegram и документацию; это не только пустая страница проекта.

## Что уже находится в Git

- Исходники экспериментального Windows-клиента на основе Telegram Desktop 7.3.5 с изменениями AyuGram.
- Исправления компиляции и линковки, workflow Windows x64 Debug и кэш зависимостей.
- Название mTelegram, mTelegram.exe и стандартные значки Telegram.
- Полная техническая сводка в mTelegram-handoff.txt.

## Что нужно сделать владельцу в интерфейсе GitHub

1. Для имени репозитория mTelegram открыть Settings → General → Repository name, ввести mTelegram и нажать Rename. Сейчас репозиторий ещё называется AyuGramDesktop. Переименование через подключённые инструменты не выполнялось.
2. Если эта оформленная ветка будет основной страницей проекта, выбрать ветку mtelegram-project основной в настройках Default branch. Сейчас default — dev; она не изменялась.
3. После успешной сборки скачать Windows-артефакт, создать тестовый предварительный релиз и приложить ZIP как asset. Не выбирать автоматически генерируемый Source code ZIP вместо бинарного файла.

Для публикации взять код из успешного коммита сборки, указать номер основы, Debug x64 и отсутствие проверки работы приложения. Предлагаемое имя файла — mTelegram-Windows-x64-Debug.zip. Не обозначать тестовую сборку как стабильную.

Здесь нет опубликованного релиза или автоматически работающей публикации. Раздел Releases предназначен для постоянных загрузок; Actions пока служит временным источником тестовых сборок.

## Android

Android-версия входит в план проекта, но пока не реализована. Потребуется выбрать исходный Android-клиент, перенести нужные изменения, настроить отдельную сборку и подпись APK, проверить работу. Ключ подписи хранить вне исходников и не публиковать в Git.

Код Android можно вести отдельным репозиторием или отдельной веткой. Не следует сейчас переносить существующий Desktop в новую папку ради общего дерева: это затронет пути CMake и рабочую сборку без готовой Android-кодовой базы.

После появления APK его можно публиковать рядом с Windows ZIP в релизах проекта; указать отдельные версии и статус каждой платформы.
